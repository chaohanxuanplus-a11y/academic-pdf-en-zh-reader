## 1. 设计结论

2026-09-10 责任声明修订：每份成功交付的 PDF 必须在文件末尾保留固定责任声明。
原末页安全区域放不下时追加专门声明页，并向用户明确提示；不能省略声明、
挤占正文或虚构源页绑定。该页属于项目说明，不属于论文译文或翻译续页，
不计入译文覆盖率与注释预算，仍须通过字体、几何、内容完整性及 QA 检查。

本项目创建一个面向中文研究者的 Codex Skill：接收一份英文、具有可提取文本层且页面盒可解释的学术论文 PDF，先将每个可见页面确定性归一化到 A4 纵向画布，再生成一份固定 ISO A3 横向的双语阅读 PDF。每个常规输出页左侧放置保持矢量内容的归一化原论文页，右侧按原页版面拓扑放置完整中文译文，并增加克制的英语学习标注。

实现采用“Agent 负责语义，确定性程序负责几何”的分工：

- Agent 负责结构语义确认、英中翻译、重点判断、术语与表达选择、图表解读和独立语义复核。
- 程序负责 PDF 解析、页面拓扑、固定字号换行、坐标求解、虚线、续页、矢量合成以及全部可机械验证的硬性 QA。
- Agent 不直接自由绘制 PDF，也不直接决定最终坐标；相同的规范化结构、冻结译文、复核结果、标注、配置、代码、字体和运行时指纹必须得到相同布局。

核心技术栈选择：

- `pdfplumber` / `pdfminer.six`：读取字符、文字行、矢量线、图像边界和字体信息。
- `ReportLab`：使用确定坐标生成右侧矢量文字、颜色、下划线和灰色虚线；字体测量与绘制使用同一引擎。
- `pypdf`：创建 A3 页面并将原 PDF 内容流以矢量方式合入左半页，再合入右侧翻译覆盖层。
- `fontTools`：检查字体名称、TTC 子字体、字符覆盖、版本和哈希。
- `pypdfium2` + `Pillow`：内部渲染回归和视觉 QA；最终准入前另行核验并记录其全部二进制第三方许可。
- Noto Serif SC Regular / SemiBold：中文正文与标题的固定 OFL 字体；从官方固定版本的区域 TrueType 变量字体可复现地生成静态 400/600 实例，并固定源与输出 SHA-256。

不把 Typst 作为核心排版器。Typst 适合一般流式排版，但本项目需要固定锚点、分级局部释放和最小扰动坐标求解；采用绝对定位后，Typst 的分页优势也不再明显。Typst可以用于视觉原型或回归对照，但不进入默认运行链。

## 2. 目标、成功标准与非目标

### 2.1 产品目标

1. 让中文研究者高效、准确地理解英文论文。
2. 通过与原文相邻的克制标注帮助用户学习专业术语、学术表达和地道句式。
3. 保留原论文作为逐页证据，不用重新排版的英文替代原件。
4. 在不同论文和重复运行中保持稳定、整洁、可打印的版式。

当“中文阅读”与“英语学习辅助”发生空间冲突时，中文完整译文永远优先。

### 2.2 最高优先级不变量

以下条件同为硬约束，任何算法不得牺牲：

1. 阅读顺序正确。
2. 中文正文完整，不删译、不截断、不用摘要替代。
3. 中文正文使用全篇固定字号，不因溢出按页或按块缩小。
4. 文字、下划线、虚线和辅助块之间零重叠，全部位于合法页面区域。
5. 中文正文是主体；暗橙色教学内容不得挤占正文或迫使正文缩字。
6. 无乱码、缺字、字体未嵌入或同一语义角色字号漂移。
7. 相同规范化结构、冻结译文、复核、标注、配置、代码、字体和运行时指纹产生相同 `layout.json` 和视觉几何。

### 2.3 v1 输入边界

v1 只接受：

- 单个学术 PDF；页面尺寸不限于 A4，但显示方向下的 CropBox 和旋转必须可解释并可确定性放入 A4 纵向画布。
- 以英文为主要自然语言。
- 正文具有可提取文本层。
- 未加密、未损坏，不要求保留数字签名。

预检发现扫描件、正文不可提取、加密、损坏、页面盒或旋转不可解释、页面方向语义混乱或拓扑无法可靠判定时，必须在翻译前停止，不得静默生成貌似成功的低质量 PDF。页面不是 A4 本身不得触发停止。

### 2.4 v1 非目标

- OCR 与扫描件恢复。
- 重新排版或修改左侧英文原文。
- 多语言对、多文件合订或批量服务器服务。
- 在线公开托管论文全文或译文。
- PDF 表单、附件、JavaScript、数字签名和交互式注释的继承。
- 逐单元人工编辑器；用户更正通过后续对话和个人纠错库处理。

## 3. 内容范围

### 3.1 必须完整翻译

- 论文标题。
- 摘要。
- 关键词。
- 一级及以下小标题。
- 正文段落。
- 图题和表题。

### 3.2 不机械翻译

- 作者姓名、作者单位/机构、DOI、URL、期刊卷期页码和其他标识符不在右侧翻译，保持在左侧原文中。
- 页眉、页脚、页码、脚注、尾注和致谢不进入右侧翻译与覆盖率。
- 公式、变量、代码、化学式和纯数据不改写；其周边说明必须翻译并保持引用关系。
- 参考文献条目不翻译、不在右侧重复；只翻译“References”等章节标题。
- 图表本体、表格单元格和图内文字不做逐项完整翻译。图题、表题以黑色完整翻译；可可靠读取的图表变量、趋势、关键数据和阅读提示以较高优先级暗橙色内容呈现。

上述“不机械翻译”对象不计入译文覆盖率分母，但必须在结构模型中有明确类型，不能被误判为遗漏。

## 4. 冲突裁决顺序

镜像 band/栏结构属于硬结构约束，与完整准确的主体翻译、阅读顺序、固定字号、零重叠和无乱码一起不可牺牲。在结构与对齐要求中，只有首行纵向严格对齐可以在空间冲突时让步；可选暗橙内容按下述裁剪顺序处理。

可裁剪内容只按以下顺序比较：

1. 完整主体翻译、标题、图题和表题：不可裁剪。
2. 必要的图表暗橙色阅读内容：优先保留，可压缩为最小可靠信息。
3. 普通术语、表达和句式的暗橙色学习内容：先推迟，再缩减或删除。

空间仍不足时，在保持镜像拓扑的前提下执行局部重排、整栏重排和最终续页。新增续页仍然是最后手段，但始终优于删译、缩字、乱序、重叠或破坏镜像分栏。

## 6. 作业生命周期与中间契约

每次运行以源 PDF 的 SHA-256、`job_id` 和 `translation_revision` 建立临时作业目录。状态严格单向推进：

```text
initialized
→ preflighted
→ extracted
→ translated
→ independently_reviewed
→ annotated
→ laid_out
→ rendered
→ validated
→ finalized
```

每一步原子写入并校验上一状态的哈希，失败不得伪造后续状态。恢复中断的同一 `job_id` 时可以复用已经验证的批次；用户发起一次新的重新运行时，即使源文件和配置相同，也必须创建新的 `translation_revision` 并重新翻译，措辞允许变化。确定性布局的比较条件是同一份已经冻结的 `translation.json`，不能把模型每次生成的文字也假定为字节相同。

正常交付目录只出现最终 PDF；内部 JSON 和 QA 记录位于临时作业区，并遵循第 16 节的数据生命周期。

核心中间文件：

- `source.json`：页面框、横向 band、栏、内容块、阅读顺序、字符与首行几何；图表对象 ID、caption ID、正文引用关系、可提取的轴/图例/单元格/脚注文字及置信度。
- `units.json`：跨栏和跨页合并后的语义单元及其源片段映射。
- `translation.json`：完整译文、术语决策和可定位 span。
- `review.json`：独立审校问题、修复和最终状态。
- `annotations.json`：暗红重点、暗橙教学、图表解读和亮红歧义标记。
- `frame-graph.json`：右侧全部原生 frame、可插入续页 frame、有序边、合法断点和 `unit_part` 行范围。
- `layout.json`：每一行、每一块、每条虚线、续页和坐标的确定性结果。
- `render-manifest.json`：源页变换、字体文件及 SHA-256、字号、颜色、依赖版本和映射关系。
- `qa.json`：全部内部验收结果。任一硬门禁失败时，不产生可交付文件。
- `provenance.json`：原始上传哈希、归一化 PDF 哈希、配置哈希、代码版本、上游来源和运行环境。
- 临时 `figure-assets/`：图表的受限可见裁剪，只供当前作业的图表解读和内部复核，绝不进入交付物或公开测试数据。

所有文件均使用版本化 JSON Schema。稳定 ID 由页码、阅读序号、角色和源字符范围生成；不得使用随机 UUID 影响重复运行。

## 7. 端到端工作流

### 7.1 预检

在发送论文内容给翻译 Agent 前检查：

1. PDF 可打开、未加密且页树有效。
2. 旋转和 CropBox/MediaBox 可解释；记录显示方向下的可见宽高，不因非 A4 尺寸拒绝。
3. 每页正文具有足够的可提取字符和合理字符坐标。
4. 字体、资源对象和内容流不会要求执行活动内容。
5. 估计的页面拓扑置信度达到下限。

活动 JavaScript、附件和文档级动作不复制到输出；左侧只合入页面可见内容及其必要资源。

预检通过后，受限 worker 以原始上传哈希和预检哈希为父级，生成不可变的 `normalized-source.pdf` 与 `normalization.json`。归一化 PDF 的哈希与原始上传哈希分别保存；后续提取、拓扑和渲染只使用作业内已绑定的归一化 PDF。

### 7.2 结构提取

一次性提取每页字符、文字行、矩形、曲线、图像、字体、颜色和页面框。页眉、页脚、页码、重复水印通过跨页位置和内容重复率识别，不进入正文翻译。

结构识别采用确定性的“横向 band + band 内栏”区域树：

1. 按字符和图形 bbox 建立页面占用投影。
2. 递归 XY-cut 查找持续空白沟槽。
3. 跨栏标题、摘要、图表和分隔线形成横向 barrier，将页面切为多个 band。
4. 每个 band 独立识别 1–N 栏；“多栏”统一指两栏及以上。
5. 结合字体层级、编号、关键词、位置和邻接关系识别标题、摘要、关键词、小标题、正文、图题和表题；同时把作者/机构、页眉页脚、脚注尾注、致谢、公式、参考文献、表格单元格和图内文字标成明确的非翻译角色。
6. 生成阅读顺序 DAG，再稳定拓扑排序；相同几何下使用页面、栏和源对象序号作确定性 tie-break。

GROBID 只可作为用户另行安装的可选本地服务，为语义标签提供提示；它不能决定几何、不能成为默认必需依赖，也不随 Skill 分发其 `pdfalto` 组件。

若 band、栏数或阅读顺序低置信度，Skill 可通过内部页面渲染进行结构复核；仍无法可靠确定时以 `NEEDS_TOPOLOGY_REVIEW` 停止，不静默降级为单栏。

### 7.3 语义单元合并

英文段落可能恰好在分栏处或分页处被截开。`units.json` 必须将属于同一语义段落的多个源片段合并为一个翻译单元，判断依据包括：

- 连字符和断词。
- 句末标点、大小写和缩进。
- 栏与页面阅读顺序。
- 字体、行距和段前段后关系。
- 引文、公式和列表的连续性。

中文译文不机械复制英文的栏末或页末断点。它作为完整段落连续流动，只有中文目标栏确实放不下时才在合法行界自然续排。

### 7.4 翻译

翻译 Agent 读取完整论文结构、论文级术语表、必要前后文、已适配当前语境的个人纠错建议，以及图表对象与正文引用关系，并按稳定单元 ID 返回结构化 JSON。图表解读还可读取临时安全裁剪和可提取的轴、图例、单元格文字；视觉或结构置信度不足时不得臆测，只输出 caption 的完整翻译和明确可读的最小标签信息。批次应用前严格检查：

- 单元 ID 完全一致，无缺失、重复或多余项。
- 数字、单位、区间、统计量、方向和符号得到保留。
- 引文编号、图表编号、公式编号保持对应。
- 术语在相同语境下保持一致。
- 不输出排版坐标或自由格式 Markdown。

翻译质量的五个第一原则是：

1. 事实准确。
2. 程度和强弱表达准确。
3. 因果、条件、转折、比较等逻辑关系准确。
4. 数据、单位、范围、统计量和正负方向准确。
5. 专业术语准确。

在此基础上，中文必须地道、通顺；不得把“可能、提示、相关”强化为“确定、证明、导致”，也不得遗漏否定、限制条件、样本范围和不确定性。

### 7.5 独立语义复核

翻译完成后，由未参与该批次翻译的独立 Agent 比较英文源单元与候选译文。复核不是一般润色，而是逐项检查上述五类准确性，并输出结构化问题：

- `hard_error`：事实、程度、逻辑、数据或术语错误，必须修复后重审。
- `style_improvement`：不影响含义但可改善中文表达。
- `unresolved_ambiguity`：现有上下文无法可靠消除且会影响实质理解。

生产 Agent 应用修复后，独立 Agent只复核改动单元、邻接单元和共享术语单元。存在未修复 `hard_error` 时禁止排版。最终仍未解决的实质歧义进入亮红色标注，而不是被隐藏或猜成确定答案。

如果运行环境无法提供真正独立的复核 Agent，Skill 必须停止并说明缺少必要能力，不得把同一生成步骤伪称为独立审校。

### 7.6 标注选择

标注只在译文定稿后生成，并使用无循环的两阶段流程：

1. 先锁定主体译文、暗红 span、歧义标签和图题/表题，完成一次 mandatory-only 布局。
2. 对全部暗橙候选预先使用最终字体和栏宽测量，按稳定评分和单元 ID 排序。
3. 图表暗橙先逐项试放：每个候选都重新运行有限范围求解；至少保留一条理解所必需且有证据的图表说明时，允许在整栏无解后触发续页。
4. 普通术语/表达暗橙随后逐项试放；只有在不新增续页、不缩字且不破坏硬约束时才接受，否则推迟到后续出现位置或删除。
5. 候选集合一旦确定即冻结，再执行最终布局；不得根据最终页面重新生成候选，因而不会形成布局—内容循环。

### 7.7 布局、渲染和 QA

版面求解器读取冻结的结构、文本、复核和标注，先生成 `frame-graph.json`，再生成不可变 `layout.json`；ReportLab 按其坐标绘制右侧覆盖层，pypdf 合并左侧原页与覆盖层，最后执行结构、几何、字体、渲染和内容验收。只有全部通过才原子移动最终 PDF 到交付目录。

## 8. 中文字体与排版样式

### 8.1 字体

- 正文主字体：Noto Serif SC Regular，黑色。
- 标题和小标题主字体：同家族 SemiBold；不混用系统字体。
- 数学/符号回退：Noto Sans Symbols 2 Regular，仅处理主字体确实缺失的 grapheme，保持相同点数和基线。
- 禁止系统字体自动 fallback。缺字必须在渲染前发现；未配置合法回退时硬失败。

门槛 0 首先按原方案实测了 Noto CJK 官方 `Serif2.003` 的两个静态 OTC：SC face 均可由 name table 唯一识别，但二进制使用 CFF 轮廓，`reportlab==5.0.1` 明确拒绝并报告 `postscript outlines are not supported`。因此运行时不使用这两个 TTC，也不使用系统字体或栅格兜底。

通过门槛的 Serif 主字体改为同一官方 tag/commit 的区域 TrueType 变量源 `Serif/Variable/TTF/Subset/NotoSerifSC-VF.ttf`。`bootstrap_fonts.py` 使用固定 `fonttools==4.63.0`，分别把 `wght` 固定为 400 和 600、生成静态实例、更新 name table 并关闭时间戳重算，得到 `NotoSerifSC-Regular.ttf` 与 `NotoSerifSC-SemiBold.ttf`。转换是确定性的，且源文件、转换参数、源与输出 SHA-256、Git blob、修改状态、OFL-1.1-RFN 和 Reserved Font Name `Source` 均写入 `font-manifest.json`。符号字体固定取自 Noto Symbols 2 `v2.008` 官方 Release 的 `NotoSansSymbols2-Regular.ttf` 成员并保持未修改，使用 OFL-1.1。任何来源、哈希、名称表、字符覆盖、嵌入、ToUnicode、提取、测宽、渲染或重复运行检查不符都停止。

`FontRunResolver` 按 grapheme cluster 使用固定字体链生成不可变 run 列表。换行测量和最终绘制必须复用同一 run 列表；每一行的 ascender、descender 和 line box 取该行全部 run 的确定性最大值。这样允许受控符号回退，同时不破坏测量—绘制闭环。

### 8.2 字号和行距

从已识别英文正文文字中计算按字符加权的主字号众数；异常跨度由稳健中位数过滤。得到的正文点数作为全篇中文正文固定字号，写入 style contract，之后不可按页或按块变化。

- 正文行距按固定比例从正文点数派生，并在整篇保持一致。
- 图题、表题使用固定 caption 角色字号。
- 标题和各级小标题分别从原文角色字号映射为固定角色字号；标题过长只换行，不缩字。
- 暗橙色辅助文字使用一个全篇固定辅助字号，默认约为正文的 86%，但不得小于可打印下限；具体数值在原型标定后写入版本化配置。
- 亮红色“（可能存在歧义）”与所在译文角色字号完全相同。

所有测量和绘制均使用 ReportLab 注册的同一字体链、同一 `FontRunResolver` 结果、同一字号和同一字符串。换行宽度统一调用对应 run 的 ReportLab 字体度量；不允许一种引擎测量、另一种引擎绘制。

### 8.3 中文换行

实现确定性的 Unicode/CJK 换行器：

- 遵守中文行首、行末禁则。
- Latin 单词、数字、单位、统计表达和引用编号尽量不拆。
- URL/DOI 只在安全分隔符处断开。
- 允许中文段落在目标栏末自然拆行，但尽量避免孤行和寡行。
- 使用固定优先级和稳定 tie-break，不让词典或运行环境改变断行。

## 9. A3 页面与镜像拓扑

### 9.1 固定几何

使用 ISO 毫米值换算 PDF point：

- A4 纵向：约 `595.276 × 841.890 pt`。
- A3 横向：约 `1190.551 × 841.890 pt`。
- 左原文页：`x = 0..595.276 pt`。
- 右译文页：`x = 595.276..1190.551 pt`。

每页先按声明旋转得到显示方向下的 CropBox，再将其宽度与 A4 宽度、其高度与 A4 高度分别比较。两轴均可放入时保持严格 1:1，并在不足的轴上居中补白；任一轴超过 A4 时，只使用一个统一比例做恰好足以放入的最小缩小，再居中补白。归一化绝不放大、裁切或非等比拉伸，也不因原始页面不是 A4 而失败。归一化后的固定 A4 页以 1:1 放入 A3 左半页，不截图、不栅格化、不重新排版。

### 9.2 右侧固定网格

右侧保留固定内边距和中心连线路由带。对每个源 band，在右侧创建相同栏数和相同比例的栏宽、栏间距：

- 跨栏或单栏 band：右侧同样跨栏或单栏。
- 两栏及以上 band：右侧同样按该 band 的栏数分栏。
- 第一页上部不分栏而下部双栏时，右侧使用同样的混合拓扑。
- 源侧图表 band 在右侧仍保留同样的跨栏/栏内结构和阅读序号，但不保留与原图等高的空白占位；右侧 band 只容纳黑色 caption 译文和最终获准的 1–3 条暗橙说明，其高度由这些实际内容确定，后续 band 按最小重排规则移动。

所有跨栏/单栏译文块使用一个固定左边界。多栏时，每个镜像译文栏具有自己的固定左边界；同一栏内所有译文块完全对齐，跨页和重复运行不漂移。不得因为虚线长度或源块位置改变译文文字的起始 x 坐标。

正文段落不使用任意首行缩进，以固定段间距区分段落；这样每个栏的译文左边界保持明确一致。

### 9.3 首行锚点与虚线

标题、摘要、关键词、正文段落、小标题、图题和表题在单栏或跨栏 band 中建立“源首行 baseline → 译文首行 baseline”锚点。两栏及以上 band 不绘制虚线，只将首行纵向接近作为软目标。

虚线规则固定：

- 中性灰色、低对比度、固定细线宽和固定 dash pattern。
- 起点位于源首行末端之后的空白处，终点止于译文固定左边界之前，不触碰文字。
- 首行能够对齐时使用水平线。
- 译文因溢出上下移动时，使用中心路由带内的圆角三段折线；垂直段不得进入正文。
- 源译阅读顺序单调，连线不得互相交叉；通道冲突时按稳定单元序号分配固定 lane。
- 任一虚线与正文、图形说明或其他非允许对象相交即 QA 失败。

## 10. 固定字号下的最小重排求解

### 10.1 行片段与 FrameGraph

固定字号换行首先把每个语义单元变成有序 line box。`unit_part` 表示同一单元的一个连续行范围，记录 `unit_id`、起止行、源片段范围和是否为首段/续段。语义单元保持完整，`unit_part` 只是排版片段，不能成为新的翻译单元。

随后建立全局、有序的 `FrameGraph`：

- 每个源页的每个 band/栏对应一个原生右侧 frame 节点，具有稳定 ID、栏宽、拓扑角色、源页和源 band。
- 有向边只按正确阅读顺序连接同页后续栏、合法的下一 band 和下一页。
- 普通单元不得为了塞入页面越过自己的源页组去占用无关下一源页；整页无解时插入续页节点。
- 如果一个语义单元的英文源片段本来就跨到下一栏或下一页，则该单元的 `unit_part` 可沿对应原生边自然流动，不在英文断点机械切开。
- 每条边记录可用的块间、句间和行间断点，以及孤行、寡行和标题随文约束。
- 续页节点在初始图中是候选节点，只有原生 frame 无解时由 DP 激活；它们重复引用对应源页并沿用相同拓扑。

只在语义单元第一次出现处创建首行锚点；后续 `unit_part` 不重复产生同一段落的虚线。

### 10.2 band 高度和 frame 几何

几何求解分两层，避免跨栏 barrier 与栏内容互相循环依赖：

1. 在固定栏宽下完成字体 run、换行和合法 `unit_part` 候选。
2. 对每个 band 计算最小内容高度 `H_b`：跨栏块取自身流高；多栏 band 取各栏在合法分配下最小流高的最大值，并加固定内边距/间距。
3. 把 band/barrier 当作顶层有序链，根据源 band 锚点和 `H_b` 求纵向位置。
4. band 边界确定后，生成各栏最终 frame；再在每个 frame 内求块和 `unit_part` 位置。

源侧图表 band 的右侧 `H_b` 只由 caption 译文和已获准橙色说明计算，不保留原图高度。

### 10.3 局部位置优化

固定窗口内，每个不可再拆的布局块具有高度 `h_i`、期望位置 `a_i` 和顶坐标 `y_i`：

```text
y[i+1] >= y[i] + h[i] + gap[i]
frame.top <= y[i]
y[i] + h[i] <= frame.bottom
minimize Σ weight[i] × |y[i] - a[i]|
```

影响范围由分级窗口本身控制，不把“移动块数最少”错误塞进 PAVA 目标：

1. 只释放当前块。
2. 加入相邻上一块和下一块。
3. 按阅读顺序半径逐步扩大局部窗口。
4. 局部窗口均无解时，释放整个当前栏；涉及跨栏 barrier 时释放对应 band。
5. 原生 FrameGraph 仍无解时，才进入续页 DP。

未进入当前窗口的坐标冻结。对每个固定窗口，先对最大允许位移 `D` 做确定性二分，找到满足硬约束的最小 `D`；再在该边界内用有界加权 L1 isotonic regression / weighted-median PAVA 最小化总绝对位移。段落拆分只由 FrameGraph 的合法断点和续页 DP决定，不属于 PAVA 目标。

首行严格对齐是强偏好而非硬约束；它必须让位于完整译文、阅读顺序、镜像拓扑、固定字号和零重叠。

### 10.4 续页 DP

只有原生 frame 经整栏/band 重排仍无可行解时，才在 FrameGraph 上激活续页节点并用动态规划选择方案。DP 按以下字典序优化：

1. 新增续页数最少。
2. 语义单元拆分数最少。
3. 优先在完整语义块之间，其次自然句界，最后合法行界断开。
4. 孤行、寡行和标题随文违规为不可行，而非低分方案。
5. 相同代价按稳定 `unit_id`、行号和最早合法断点裁决。

续页插在对应源页之后，左半页重复引用同一原文页内容流，右半页沿用相同拓扑、固定字号和阅读顺序，并用右侧固定位置的低调“译文续页”标识避免误认。重复原页保持原样；标识不覆盖左侧原文。

## 11. 三类视觉标注

颜色值属于版本化设计令牌，原型阶段做打印测试后固定；不得按论文随意变化。推荐初值：正文近黑 `#111111`，暗红 `#7F1D1D`，暗橙 `#A84F08`，亮红 `#D00000`，虚线灰 `#9A9A9A`。

### 11.1 暗红色重点

- 仅标核心观点、关键推理、关键结果和核心结论。
- 摘要不使用暗红色，因为摘要整体已经重要。
- 目标比例约 6%，不是最低配额；不得为达到 6% 强行标色。
- 硬上限 10%，超过即阻断交付。
- 分母为排除标题、摘要、关键词、橙色内容和歧义标签后的中文主体字符；忽略空白和纯标点。
- 按“核心结论 > 直接支撑结论的数据/结果 > 关键机制或推理 > 其他观点”排序，在自然短语或句子边界选择，直至接近目标。
- 暗红只改变 glyph 颜色，不改变几何；亮红歧义下划线优先显示，不能被暗红掩盖。

### 11.2 暗橙色术语和表达

在对应中文译文下方用固定暗橙辅助字号写：

```text
English original — 中文意思
```

对象仅限具有专业价值或英语学习价值的术语、地道表达和句式，不追求数量。全篇先建立候选及出现次数，再决定标注位置：

- 默认在首次出现处标注。
- 只出现一次的高价值项目优先保留在该处。
- 后文还会出现的项目在前部拥挤时允许推迟到后续出现位置。
- 相同表达原则上只标一次。
- 空间不足时先删除低价值项，再推迟可后置项，最后只保留最核心内容。

暗橙内容没有最低占比；宁可没有辅助，也不得挤占主体翻译。

### 11.3 图表暗橙色内容

图题、表题是黑色完整翻译。图和表本体的暗橙块可以包含：

- 轴、变量、分组和缩写的必要中文解释。
- 最重要趋势、比较、异常值或结论。
- 理解图表所必需、但正文未充分说明的最小提示。

每个图表默认最多输出 1–3 条简洁、可由图表或正文直接支持的发现。它的优先级低于完整主体翻译，高于普通术语/表达辅助。空间不足时先删除普通暗橙内容，再压缩图表解读到理解所需最小内容；不得删除图题、表题译文。仍无空间则进入重排和续页。图像不可读或表格结构低置信度时不编造发现。

### 11.4 亮红色歧义

- 只用于会影响事实、程度、逻辑、数据或术语理解的最终未决歧义，不用于一般低信心或风格偏好。
- 对有歧义的中文 span 使用亮红色下划线。
- 每个稳定 `ambiguity_key` 第一次出现时，在 span 后以相同字号、亮红色写“（可能存在歧义）”。`ambiguity_key` 至少由英文表达/句法结构、候选含义、学科语境和歧义原因构成，不能只按“术语歧义”等宽泛 QA 大类合并。
- 标签和下划线作为主体尺寸参与测量，不能缩小或覆盖。
- 若后文语境或独立复核解决歧义，必须回改译文并移除标记。
- 不另行向用户生成质量报告。

## 12. 个人纠错记忆

只有用户对已经亮红标注的歧义给出明确更正时才写入个人库；用户给出该更正即授权记录该条。普通翻译意见、普通模型输出或推测出的偏好不自动成为长期记录；未来若要记录普通译法偏好，必须由用户显式要求。

存储采用当前用户的全局个人 SQLite 库，位于 Skill 包和项目仓库之外，跨论文、跨作业复用，并默认加入所有项目忽略规则。项目可以读取适配后的建议，但不得拥有、复制或提交该数据库。每条记录至少包含：

- 原英文表达及规范化形式。
- 用户认可的中文译法。
- 用于去重和来源隔离的上下文哈希指纹。
- 不含整篇论文的最小结构化语境：学科、句法功能、核心搭配、语义标签和极短必要片段。
- 学科领域。
- 原词性、句法功能和目标语法功能。
- 用户更正来源、创建时间、最后确认时间和版本。
- 适用/冲突记录与撤销状态。

后续遇到相同或相似表达时，把记录作为高优先级证据提供给翻译 Agent，但受学科域和语境约束，不机械全局替换：

- 可跨词性参考，但必须重新完成语法适配。
- 旧偏好不能凌驾于新语境的明确证据。
- 使用后仍检查专业语境、事实、逻辑和中文通顺度。
- 冲突无法解决时重新进入歧义标注。

提供查看、导出、逐条删除、撤销和全部清除功能。个人库不得进入 Git、公开测试数据、日志或发布包。

## 13. PDF 合成与确定性

### 13.1 渲染

1. pypdf 创建无活动内容的 A3 空白页。
2. 将源页可见内容及所需资源以固定变换合入左半页。
3. ReportLab 以 `invariant` 模式根据 `layout.json` 生成 A3 大小的右侧矢量覆盖层。
4. pypdf 将覆盖层合入 A3 页面。
5. 规范化文档元数据、对象顺序和 trailer ID；不让当前时间进入布局或可见内容。

左侧源页继续保持可缩放的矢量文字和图形；右侧中文保持可选择、可搜索的矢量文本。不得用整页截图作为任何一侧的兜底。

### 13.2 确定性规则

- 坐标内部使用整数 milli-point，最终绘制前才转换为 point。
- 全部排序使用稳定 ID tie-break。
- 字体、依赖、颜色、间距和换行规则锁定版本和哈希。
- 所有 JSON 在哈希前转换为 UTF-8、Unicode NFC、排序键、无非有限数值的规范形式；几何只用整数，数组顺序由 schema 明确，序列化采用固定 canonical JSON 规则。
- `layout_input_hash` 覆盖规范化的 `source.json + units.json + translation.json + review.json + annotations.json + frame-graph.json + config + code/version + dependency lock + font hashes + Python/Unicode/runtime fingerprint`。任何一项变化都产生新的布局版本。
- 布局阶段不再进行随机或生成式决策。
- 重跑验收以相同 `layout hash` 和渲染几何为硬标准；在元数据规范化完成后进一步追求字节级一致。

## 14. QA 与发布门禁

### 14.1 语义 QA

- 所有应译单元出现且只出现一次。
- 单元顺序和源阅读顺序一致。
- 独立复核无未解决 `hard_error`。
- 数字、单位、区间、统计量、图表编号和引用编号通过规则化对照。
- 术语一致性通过，同时允许有语境证据的词性和译法变化。

### 14.2 几何 QA

- 输出每页精确为 A3 横向。
- 归一化页面的缩放与补白符合“能放入则 1:1，超出才最小等比缩小”的契约；归一化后的 A4 页以 1:1 放入左侧。
- 右侧 band、栏数、栏序和固定左边界正确。
- 所有 glyph、下划线、虚线和辅助块在合法 frame 内。
- 所有对象零非法重叠；leader 不穿越文字。
- 两栏及以上 band 不存在 leader。
- 单栏/跨栏 leader 的源、译端点映射正确。
- 续页无丢失、重复、乱序和字号变化。

### 14.3 字体与视觉 QA

- 所需字体全部嵌入或子集嵌入。
- 每个待绘 Unicode code point 在已批准字体链中有 glyph。
- 同一角色字体、字号和行距全篇一致。
- pypdfium2 渲染各页，检查黑块、空白异常、裁切和对象越界。
- 左半页渲染与源页渲染在确定性容差内一致，并检查不存在覆盖左半页的新增整页大图像。
- 代表性页面生成内部接触表供独立视觉审查；不作为用户质量报告交付。
- PDF catalog、page tree、annotations 和 name tree 不含第 16 节禁止的活动内容或附件对象。

### 14.4 标注 QA

- 暗红比例目标约 6%，硬上限不超过 10%。
- 摘要中暗红字符数为零。
- 暗橙块只位于关联译文之后，且不得造成正文删除、缩字或重叠。
- 图表暗橙内容先于普通暗橙内容保留。
- 每类首次歧义标签只出现一次；所有最终歧义 span 有亮红下划线。

### 14.5 重复运行 QA

对同一完整 `layout_input_hash` 连续运行两次：

- `layout.json` 规范化哈希必须完全一致。
- 每个块和每一行坐标必须一致。
- 渲染图像差异必须为零或仅限已明确排除的 PDF 元数据。

## 15. 失败、恢复和交付

以下情况禁止交付貌似正常的 PDF：

- 源文件不满足 v1 输入边界。
- 栏拓扑或阅读顺序无法可靠确认。
- 任一应译单元缺失、重复、错序或存在未修复语义硬错误。
- 字体缺字、未嵌入或固定字号漂移。
- 任何对象重叠、越界、裁切或虚线穿正文。
- 左页被栅格替换或原文视觉失真。
- 暗红比例超过 10%。
- 暗橙内容挤占正文。
- PDF 结构检查或渲染回归失败。

同一 `job_id` 的中断作业按状态和内容哈希恢复；已经验证的提取、翻译和审校批次不重复执行。用户发起“重新运行”则创建新的 `job_id`/`translation_revision` 并重新翻译，不静默复用旧译文。源文件或关键配置变化时也必须创建新的作业版本，不能在旧结果上混合。生产完成入口保留原始 `--source-pdf` 只用于重新验证最初上传的字节身份；提取、合成、渲染和 QA 一律读取作业内已绑定的不可变 `normalized-source.pdf`，不得再从原始路径参与版面处理。

正常成功时用户只收到：

```text
<原文件名>.bilingual-a3.zh-CN.pdf
```

不附质量报告、内部 JSON 或调试文件。失败时只返回简明原因和是否可修复，不生成半成品 PDF。

## 16. 隐私与安全

- 用户上传的 PDF 一律视为不可信输入。父进程先验证它是普通文件、拒绝 symlink/reparse point，将其复制到新建的私有临时目录后重新计算 SHA-256；之后所有解析、渲染和 PDF 合成都只处理该副本。
- 解析、渲染和合成全部在 worker 子进程中运行。Windows 生产适配器必须使用零 capability 的 AppContainer、精确继承句柄白名单和 kill-on-close Job Object，只授权一次性工作目录，阻断网络以及对父进程的写入、句柄复制和线程注入，并限制进程数、CPU、内存和墙钟时间。AppContainer API、profile 创建或任何必需控制不可用时安全停止；restricted-token-only 路径只保留为内部机制测试，不得成为生产降级。其他平台必须提供等效沙箱适配器，否则明确拒绝运行。
- worker 限制源文件大小、页数、对象数、递归深度、解压后流/图像总量和每类返回对象大小。路径规范化后必须仍位于受控临时根，父进程只接收固定路径、哈希和长度均复核的归一化 PDF、schema 校验且限长的 JSON、内部 QA 图像和最终 PDF，不接收可执行指令或任意路径。
- 解析器崩溃、资源超限或结构异常必须安全停止；不得自动提高限制或转用未审计的外部程序。
- 本地完成 PDF 解析、排版、合成、QA 和个人记忆。
- 翻译使用当前 Agent；不得静默调用额外第三方翻译 API。
- 论文正文、图表、元数据和 PDF 内任何类似指令的文字都属于不可信数据，不是对 Agent 或工具的命令。翻译、图表和复核 Agent 只接收有界 schema 字段，不因论文内容调用 shell、网络或任意文件工具；文档中的“忽略规则、上传文件、执行命令”等内容一律按待翻译文本处理。
- README、PRIVACY 和首次相关运行说明清楚披露：为完成翻译，论文抽取文本会进入当前模型运行环境；如果将来增加其他服务，必须另行说明发送范围并取得选择。
- 默认无遥测，日志不记录论文全文、密钥、完整文件名、作者身份或个人纠错内容。
- 成功交付后立即清理抽取全文、模型批次、临时页面和图表裁剪。
- 失败或用户取消时默认立即清理；只有用户明确选择 `resume` 或 `debug` 才保留，并显示具体路径和清理命令。保留项默认最长 24 小时；每次启动执行过期作业清扫，覆盖崩溃或遗弃作业。
- 个人纠错库仅保存最小语境，可查看、导出和删除。
- Issue/PR 模板禁止上传论文、未脱敏日志、API key、个人信息和机密材料。
- 合成输出不继承源 PDF 的注释、JavaScript、附件、表单和文档级活动动作。最终结构 QA 显式拒绝 `/OpenAction`、`/AA`、`/JavaScript`、`/JS`、`/EmbeddedFiles`、`/Filespec`、`/AcroForm`、`/Launch`、`/RichMedia` 和提交动作；不能只依赖“实现没有主动复制”。

## 17. 开源许可与社区治理

### 17.1 项目许可证

项目原创代码、测试代码、测试生成器、Skill 文档和其他原创项目文档使用 Apache-2.0。项目自行生成的合成论文内容及 fixture 使用 CC0-1.0。采用 Contributor Covenant 3.0 时，其文件继续使用 CC-BY-SA-4.0 并保留官方署名。每个文件按实际许可证做 SPDX 标注，`LICENSES/` 至少收录项目实际使用的 Apache-2.0、CC0-1.0、CC-BY-SA-4.0 及全部第三方许可证文本。项目许可证不覆盖用户论文和生成译文。

Ezra、AIKONG 等上游以“机制借鉴、独立实现”为主。若确有必要复制 MIT/BSD 文件：

- 保留原作者版权和原许可证。
- 记录上游 URL、commit、原文件路径和修改说明。
- 文件级 SPDX 标注使用实际许可证，不把它改写成项目 Apache-2.0。
- 大量保留历史时采用正式 fork/保留 Git 历史；孤立定向复用则在 `UPSTREAMS.md` 和文件头完整记录。

### 17.2 依赖准入

默认核心允许经审核的 Apache-2.0、MIT、BSD-2/3-Clause、ISC、Zlib 等宽松许可证；字体单独允许经审核的 OFL-1.1。

以下项目必须专项审查，默认不得进入核心、发布包或静默下载：

- GPL、AGPL、LGPL、SSPL、MPL 等 copyleft 或文件级 copyleft 组件。
- NC、ND、仅限研究、禁止衍生、自定义模型许可证。
- 无许可证、`NOASSERTION`、`Unknown` 或只写“免费”的代码和资产。
- PyMuPDF/MuPDF、BabelDOC、pdf2zh、Ghostscript。

这是一项保守准入政策，不是对这些许可证合法性的否定。确需采用时必须先做兼容性、分发边界和义务审查。任何直接、传递、二进制、字体或运行时下载依赖在进入锁文件前都必须记录来源、版本、许可证、SHA-256 和实际发布内容；不能只审查顶层 Python 包。

### 17.3 字体、模型和测试素材

- 只使用官方来源且来源与 SHA-256 固定的 Noto/思源 OFL 字体。若为解决渲染器兼容性而从官方可变字体可复现地派生静态实例，必须固定转换工具与参数、记录源文件和产物哈希、按 OFL/RFN 要求改名，并保留 OFL 文本和版权信息。
- 不分发微软雅黑、宋体等专有系统字体。
- 默认不分发模型权重、tokenizer 或训练数据；未来新增时分别审查代码、权重、tokenizer、数据和使用限制。
- 不把用户论文、普通期刊论文或完整译文作为 fixture、截图或 Release 资产。
- v1 测试、截图和演示只使用项目自行编写并以 CC0-1.0 释放的合成论文。
- 未来如确需外部 CC BY 材料，必须先专项审查并在 `TEST_DATA_ATTRIBUTION.md`/资产清单记录标题、作者、原始来源、准确许可证版本与链接、修改/翻译说明、展示位置，以及文章内第三方图表是否被整体许可排除；“arXiv/网站可下载”不等于可以翻译和再分发。

### 17.4 必须文件与自动门禁

仓库必须具有 `README.md`、`LICENSE`、`LICENSES/`、`NOTICE`、`THIRD_PARTY_NOTICES.md`、`UPSTREAMS.md`、`TEST_DATA_ATTRIBUTION.md`、`REUSE.toml`、`PRIVACY.md`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`SECURITY.md` 和 `CITATION.cff`。

每个 PR：

- 执行 `reuse lint`。
- GitHub Dependency Review 检查许可证白名单和已知漏洞。
- 检查新增依赖、字体、图片、测试 PDF 和下载资产的来源、版本、许可证与哈希。
- 检查 AI 辅助贡献披露和 DCO `Signed-off-by`。PR 固定字段包括：AI-assisted yes/no、所用工具类别、影响文件、人工检查与测试、是否出现 public-code match 及其来源/许可证，以及没有将机密或用户论文放入提示。CONTRIBUTING 预先说明 DCO 会公开提交身份信息，并说明可使用 GitHub noreply 邮箱但不能伪造 sign-off。

每个 Release：

- 生成资产清单并核对 `NOTICE` 与真实包内容。

## 18. 测试矩阵

所有测试材料优先用 CC0 合成论文程序化生成。

| 场景 | 必须验证 |
|---|---|
| 单栏论文 | 全部 leader、固定左边界、标题/摘要/正文对应 |
| 首页面上跨栏、下双栏 | 右侧混合拓扑一致；上部有 leader、下部无 leader |
| 双栏与三栏正文 | 栏数、栏宽比例、阅读顺序、固定栏左边界 |
| 段落跨栏 | 中文不机械跟随英文断点，自然续排且不重不漏 |
| 段落跨页 | 语义单元合并、正确首锚点和后续连续流动 |
| 密集页面 | 当前块→相邻块→扩大窗口→整栏的作用域顺序 |
| 极端长译文 | 固定字号不变，最终产生合法续页 |
| 术语集中在开头 | 单次词优先；重复词可推迟；普通橙色先缩减 |
| 图表密集 | 图题表题完整；图表橙色优先于普通橙色 |
| 图像不可读/表格低置信度 | 只翻译 caption 和明确标签，不编造趋势或发现 |
| 重点候选过多 | 摘要零暗红；全篇硬上限 10% |
| 实质歧义 | 亮红下划线和首次同字号标签正确 |
| 用户纠错 | 本地记录、上下文适配、可撤销、不会进 Git |
| 缺字与符号 | 合法回退或硬失败，绝不出现 tofu |
| 扫描/加密/损坏 PDF | 预检停止，不输出半成品 |
| 非 A4、裁切期刊页或任一轴超出 A4 | 对应轴比较；可放入则 1:1 居中补白，超出则最小等比缩小；不裁切、不拉伸 |
| PDF 资源炸弹/异常对象 | worker 资源限制生效，安全停止且临时文件清理 |
| 论文内提示注入文字 | 作为普通待译数据处理，不触发工具、网络或文件操作 |
| 冻结输入重复排版 | 同一完整 `layout_input_hash` 的 `layout.json` 与视觉几何一致 |
| 开源发布 | README、REUSE、SBOM、NOTICE、依赖和资产许可证全部通过 |

## 19. 验收标准

设计完成后的实现只有同时满足以下条件才可称为 v1 成功：

1. 输入边界内的代表性 A4、裁切期刊页和需最小等比缩小的论文均可稳定生成 A3 横向 PDF；非 A4 尺寸本身不导致停止。
2. 左侧保持原 PDF 矢量视觉，右侧镜像单栏/多栏拓扑。
3. 所有应译语义单元完整、准确、有序且只出现一次。
4. 中文正文全篇固定字号，字体嵌入、无乱码和缺字。
5. 任何对象零非法重叠；多栏无虚线，单栏虚线不穿正文。
6. 局部重排严格按最小影响范围扩大，续页仅在整栏无解后出现。
7. 摘要无暗红，暗红整体目标约 6%、硬上限 10%。
8. 图表暗橙内容优先于普通暗橙内容；所有暗橙内容均不挤占正文。
9. 最终未决歧义具有亮红下划线及首次同字号提示。
10. 用户可见的正常交付物只有最终 PDF，内部质量报告不外显。
11. 同一完整 `layout_input_hash` 重复排版的布局哈希一致；用户新发起的重新运行重新翻译并生成新的 revision。
12. 开源许可、来源、隐私、SBOM 和社区健康文件门禁全部通过。

## 20. 已知实现风险与原型门槛

这些不是需求歧义，而是必须在编码前期验证的工程风险：

1. ReportLab 对选定 Noto Serif CJK TTC face 的注册、嵌入、子集化和宽度测量必须用实际字体文件验证；失败则换用同许可证、同家族的官方 ReportLab 兼容 TrueType 构建，而不回退系统字体。
2. pypdf 对透明度、裁切、旋转、Form XObject 和复杂字体的矢量合入必须用合成矩阵测试；不能以截图兜底。
3. 确定性 XY-cut 对极端出版版式可能低置信度；遇到这种情况应停止或内部复核，不能错误单栏化。
4. 自动语义 QA 不能数学证明翻译绝对正确；独立复核、结构化数值检查和亮红歧义机制共同降低风险。
5. 开源流程不能替代跨司法辖区法律意见；达到法律复核触发条件时必须暂停发布。

原型必须先通过字体清单与闭环、安全 worker、矢量合成、混合拓扑/FrameGraph、局部求解和续页六项门槛，再扩展教学标注和个人纠错记忆。
